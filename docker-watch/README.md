# docker-watch

Маленький сторож на Go: по ssh проверяет, что нужные Docker-контейнеры на удалённом сервере
работают и здоровы, что нужные порты слушаются, и (по желанию) отмечается на втором сервере,
чтобы запасной сторож знал, что этот жив. Один бинарник, только стандартная библиотека.

Молчит, пока всё хорошо. При проблеме печатает текст и выходит с кодом 1, при исправлении
печатает «снова работает». Длительную проблему повторяет не чаще, чем раз в `REPEAT_MIN` минут.

## Сборка

```
CGO_ENABLED=0 go build -o docker-watch .
go test ./...
```

## Настройки (переменные окружения)

| переменная | значение |
|---|---|
| `WATCH_HOST` | обязательно, `user@host`, вход по ssh-ключу |
| `WATCH_CONTAINERS` | обязательно, имена контейнеров через пробел |
| `WATCH_NAME` | название в сообщениях (по умолчанию «Сервис») |
| `WATCH_PORTS` | адреса, которые должны слушаться на сервере, через пробел, например `127.0.0.1:1080` |
| `HEARTBEAT_HOST` | второй сервер, на котором выполнить команду-сигнал (необязательно) |
| `HEARTBEAT_CMD` | команда сигнала, по умолчанию `touch ~/watch-heartbeat` |
| `REPEAT_MIN` | как часто повторять неисправленную проблему, по умолчанию 15 |
| `STATE_FILE` | файл состояния, по умолчанию `./data/docker_watch` |

Секретов нет: доступ только через ssh-ключ пользователя. На сервере нужны `docker`, `ss`, `awk`.

## Запуск

```
WATCH_HOST=user@host WATCH_CONTAINERS="app db" ./docker-watch
./docker-watch -dry-run   # всегда код 0 и не трогает файл состояния
```

Для расписания: `* * * * * ... ./docker-watch`, код выхода 1 — повод отправить сообщение.
