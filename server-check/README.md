# server-check

Переписанный на Go отдел «проверка сервера» (раньше —
bash-скрипт на /proc, df и systemctl). Делает те же проверки
с теми же порогами:

- место на диске / (85%), inodes (85%);
- доступная память (< 200 МБ), файл подкачки (≥ 80% при памяти < 500 МБ), постоянное чтение
  из подкачки (≥ 200 стр./с за 5 секунд — это и есть реальное торможение);
- нагрузка за 15 минут (> 2 × число ядер);
- службы с ошибкой (`systemctl --failed`), ssh и fail2ban, caddy — если он установлен;
- синхронизация часов с интернетом.

Та же защита от дребезга: одинаковый набор проблем повторяется не чаще раза в `REPEAT_HOURS`
часов (по умолчанию 6), новый или изменившийся набор — сразу, выздоровление — сразу, тихо.

Отличия от bash-версии: нет в проверках и порогах. Только стандартная библиотека, один
статический бинарник, пороги и кое-что из конфигурации — через переменные окружения.

## Сборка

```
export PATH="$HOME/.local/go/bin:$PATH" GOCACHE="$HOME/.cache/go-build" GOPATH="$HOME/go"
go test ./...
CGO_ENABLED=0 go build -o bin/server-check .
```

## Запуск

```
./bin/server-check            # обычный запуск: проблема — печать в stdout и exit 1, норма — молчит, exit 0
./bin/server-check -dry-run    # как обычный, но всегда exit 0 и не трогает файл состояния — для сравнения со старой версией
```

Занимает ~5 секунд (как и старый скрипт — ждёт 5 секунд, чтобы замерить обращения к подкачке).

Пороги и настройки через переменные окружения (по умолчанию — как в старом скрипте):
`DISK_MAX_PERCENT`, `INODES_MAX_PERCENT`, `MEM_MIN_MB`, `SWAP_MAX_PERCENT`, `SWAP_LOW_MEM_MB`,
`SWAPIN_MAX_PER_SEC`, `LOAD_MAX_PER_CPU`, `REPEAT_HOURS`, `SERVICES` (список через пробел,
по умолчанию `ssh fail2ban`, caddy добавляется сам, если найден), `STATE_FILE`.

## Запуск по расписанию

Пример для cron: `*/30 * * * * /usr/local/bin/server-check || notify-send ...` — при проблеме печать в stdout и код выхода 1.
